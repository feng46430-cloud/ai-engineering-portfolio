# 精选 5 大通用工程根因排障案例复盘

> 这 5 个案例横跨网络协议、Windows 文件锁并发、跨平台 Git 哈希、多 Agent 流水线可观测性与复杂前端状态渲染，共同点是不依赖重启碰运气，均定位到协议或状态流根因后修复。

---

## Case 1 · UDP 无握手直采导致的魔数 ID 映射失效（网络与协议层 · 通用模式）
- **现象**：在流式传感器/骨骼数据链路由 TCP 切换至低延迟原始 UDP 模式直测端到端延迟时，客户端无法正常匹配并渲染实体节点数据。
- **根因**：抓包对比 TCP 与 UDP 路径后发现，原始 UDP 直接绕过了 TCP 握手初始化阶段，导致数据包中返回固定十进制魔数 `actorId`，客户端按默认 `0, 1...` 索引匹配全部落空。
- **修复**：在协议接收层将未握手魔数 `actorId` 显式映射归一化为标准连续索引 `0, 1...`，打通无缓冲 UDP 延迟直测链路。

---

## Case 2 · V1 单测中 `rewind` 用例 1/12 概率偶发失败（Windows Flaky Test）
- **现象**：V1 阶段多 Agent 引擎早期单测套件（当时共 `826` 条，重构前终态为 `867` 条；归零重构后的 V2–V4 核心引擎精简为 `306/306` 条 `<1 秒` 全绿）偶发出现约 `1/12` 概率失败，在 `40–95ms` 内抛出 `400` 且报错 `chatId` 为空。
- **根因**：回溯调用链发现并非 `rewind` 逻辑缺陷，而是前置 `saveChat` 在 Windows 下执行 `tmp + rename` 原子写覆盖已存在文件时，偶发与系统索引器/杀软文件句柄冲突触发 `EPERM`。
- **修复**：在存储落盘层针对 Windows 原子替换 `EPERM` 增加受控退避重试，消除偶发失败。

## Case 3 · 变更账本门禁 60 个文件全量误报 `modified`（跨平台 Git/CI 层）
- **现象**：仅修改 3 个文件，但 preflight 变更账本校验却报告全仓 60 个文件全部变更，导致门禁失效。
- **根因**：双层叠加——① 脚本硬编码 `../..` 假设在兄弟仓库布局下解析错根目录；② 本机 `core.autocrlf=true` 使工作区检出 CRLF，而账本基准哈希按 LF 字节计算，导致每个文件 SHA 不匹配。
- **修复**：修复根目录定位逻辑并将校验哈希改为先按 LF 归一化再计算 SHA，消除跨平台换行符误报。

---

## Case 4 · 多 Agent 流水线降级原因丢失失败步骤名（可观测性层）
- **现象**：多 Agent 编排流水线异常降级时，`degradedReason` 仅打印 `"pipeline failed"`，无法定位究竟是哪个步骤失败。
- **根因**：虽然外层已有反向查找失败步骤的归因逻辑，但部分内置步骤（如 `critic` 拿不到上游正文）在进入执行前即抛错，步骤记录数组并未写入失败行。
- **修复**：在 `director-pipeline` 调度层循环外包裹异常捕获，补写明确 `stepId` 与错误信息后再抛出，恢复步骤级故障定位。

## Case 5 · 宿主隐藏楼层索引偏移与多视图前端跨平台串台（前端状态与 DOM 层）
- **现象 A（开源扩展 `chat-autobackup`）**：状态变量卡自动备份的楼层号总是与界面显示错位。  
  **根因与修复**：通读宿主 1.18.0 前端渲染源码（`redisplayChat`）证实 `is_system` 隐藏消息同样参与数组下标赋 `mesid` 占楼号，修正计数口径为最后一条消息真实数组索引。
- **现象 B（基于开源二次开发的大型前端收敛）**：多社媒平台共用视图类时，设置页开关点击无效且后台任务相互覆写页面。  
  **根因与修复**：定位到全局同名 DOM ID 被绑定到隐藏图层控件、以及 8 处硬编码同一 `viewId` 和 `</textarea>` 未转义击穿 DOM；通过平台作用域隔离、`@scope` CSS 锁定、HTML 转义与自动化回归消除串台与失效控件。
