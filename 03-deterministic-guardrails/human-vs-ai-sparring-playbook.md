# AI 评测校准、产品止损与防静默劣化记录

这里记录在 AI-NPC 实验原型（[《星海交易局》](https://github.com/feng46430-cloud/starlight-market-ai-npc-blueprint)）与多 Agent 编排工作台（V1→V4）推进过程中遇到的 3 次典型踩坑和调整思路。

---

## 1. 评测口径校准：修正 `98%+` 虚高通过率与“注入率 ≠ 表达率”

- **问题现象**：早期批量评测报告 `98.6%~100%` 通过，但实机试玩体感很差。复盘查出三处口径问题：① 脚本用 8B 模型替前台 4B 跑测；② 把“未触发敏感词”计入高权重加分项，盖掉了复读和延迟；③ 把单玩家响应时间混在 48 并发队列里测量。
- **调整思路**：改为 **Gate 0 零加分一票否决 + Phase A 空载单玩家耗时（`concurrency=1`）+ 100 分体验重权**。重跑把基线压回 [`31.2 (F)`](https://github.com/feng46430-cloud/starlight-market-ai-npc-blueprint/blob/main/evidence/benchmarks/run01_v441_baseline_31.2_F.md)，定位出 Top-3 开场白 `36.4%` 复读，同种子下一轮把开场白复读压到 `5.3%`；同时也暴露了典型的 Goodhart 权衡（单轮开场白变鲜活，但多轮心流从 `17.5` 跌到 `0.0`）。
- **“注入率 ≠ 表达率”排查**：Run 03 里旧监控记跨轮记忆通过 `24/24`，抽检 4 条对话原文发现模型在回复里实际 **0/4** 体现记忆（旧指标只检查了记忆字符串是否拼进 Prompt）。随后拆成了“检索注入率”和“对话实际表达率”两项独立指标，并记录了裁判模型仍需人工黄金集 Kappa 校准的待办。
- **防过拟合语料拆分**：用 8 个轮换分片包（424 条）+ 1 个独立封存盲考库（48 条）+ 固定种子替代固定 30 句反复调优。

## 2. 产品与架构止损：废弃低效交互与纯 Prompt 短期捷径

1. **废弃已做完的节点连线画布**：多 Agent 工作台连线画布已经做到坐标防冲突与曲线渲染，但实测高频改步骤顺序易断链，遂推倒改成有序缩进列表（前后真机对比见 [`01` 模块](../01-multi-agent-orchestrator/)）。
2. **推倒拥挤 2D 调试首屏 & 收归确定性管线**：《星海交易局》初版把所有调试信息塞在一张 2D 界面上，实机试玩出戏，遂改为 Unity 6 URP 3D 盲测剧场（隐藏底牌、折叠调试台）；同时放弃把所有规则都塞进 System Prompt 的短期捷径，把行情账本与机密披露边界收归 `S1→S6` 确定性规则层。

## 3. 防调优静默劣化：行为变更校验与零成本前置门禁

AI 交互调优里常见又难查的故障往往不是代码报错，而是**“某轮随手改了一个阈值、词表或默认提示词，几天后体验退化却找不到哪次改动引起的”**。

在私有引擎迭代仓里试行的两项约束（公开仓保留设计思路）：
- **行为变更指纹校验（`changelog check`）**：为影响模型行为的核心配置/规则建内容指纹；改动行为参数却未登记 `before→after / 潜在症状 / 回滚方式` 时直接 `exit 1` 拦住，并留存快照支持按关键词反查因果与 `diff`。
- **零成本前置检查（`preflight`）与四态兼容矩阵**：把语法校验、单测、文档一致性检查与假模型冒烟收成一键免费前检，通过后再触发付费模型调用；对外能力统一标注 `full | partial | deferred | not-goal` 减少范围歧义。
