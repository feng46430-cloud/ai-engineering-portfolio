# AI 评测打假、产品止损与防静默劣化实录

本页精选在 AI-NPC 实验原型（[《星海交易局》](https://github.com/feng46430-cloud/starlight-market-ai-npc-blueprint)）与多 Agent 编排工作台（V1→V4）中，最具代表性的 3 次真实纠偏与工程治理实践。

---

## 1. 评测打假：拆穿 `98%+` 假通过率与“注入率 ≠ 表达率”

- **假全绿根因**：早期批量评测报告 `98.6%~100%` 全绿，但实机游玩体验极差。复盘揪出三处评测设计缺陷：① 脚本拿 8B 替前台 4B 跑考；② 把“未触发敏感词”计入高权重加分项，掩盖了复读与延迟；③ 把单玩家响应时间混在 48 并发队列里测量。
- **重立尺子**：改为 **Gate 0 零加分一票否决 + Phase A 空载单玩家耗时（`concurrency=1`）+ 100 分体验重权**。重跑将基线压回 [`31.2 (F)`](https://github.com/feng46430-cloud/starlight-market-ai-npc-blueprint/blob/main/evidence/benchmarks/run01_v441_baseline_31.2_F.md)，定位出 Top-3 开场白 `36.4%` 复读坍缩，同种子下一轮将开场白复读压至 `5.3%`；同时也暴露了典型的 Goodhart 权衡（单轮开场白变鲜活，但多轮心流从 `17.5` 跌到 `0.0`）。
- **“注入率 ≠ 表达率”洞见**：Run 03 中旧监控记录跨轮记忆通过 `24/24`，抽检 4 条对话原文发现模型在回复里实际 **0/4** 体现记忆（旧指标只检查了记忆字符串是否拼进 Prompt）。现已拆分为“检索注入率”与“对话实际表达率”两项独立指标，并记录了 LLM-as-a-Judge 尚需人工黄金集 Kappa 校准的缺口。
- **反过拟合语料治理**：用 8 个轮换分片包（424 条）+ 1 个独立封存盲考库（48 条）+ 固定种子替代固定 30 句反复调优。

## 2. 敢砍沉没成本：推倒低效交互与架构偷懒

1. **废弃已开发完的节点连线画布**：多 Agent 工作台连线画布已经做到坐标防冲突与曲线渲染，但实测高频改步骤顺序极易断链，果断推倒改版为有序缩进列表（前后真机对比见 [`01` 模块](../01-multi-agent-orchestrator/)）。
2. **推倒纯 2D 密集调试首屏 & 回拉确定性管线**：《星海交易局》初版把所有调试信息塞在一张拥挤 2D 界面上，实机试玩零沉浸感，果断转为 Unity 6 URP 3D 盲测剧场（隐藏底牌、折叠调试台）；同时叫停“全塞进 System Prompt 控制”的捷径，强制把行情账本与机密披露边界收归 `S1→S6` 确定性规则层。

## 3. 防调优静默劣化：行为变更校验与零成本前置门禁

AI 交互调优中最常见且最难查的故障不是代码报错，而是**“某轮悄悄改了一个阈值、词表或默认提示词，几天后体验退化却查不到哪次改动引起的”**。

在私有引擎迭代仓中落地的两项治理实践（公开仓呈现设计思路）：
- **行为变更指纹校验（`changelog check`）**：为影响模型行为的核心配置/规则建内容指纹；凡改动行为参数却未登记 `before→after / 潜在症状 / 回滚方式` 直接 `exit 1` 拦阻，并留存快照支持按关键词反查因果与真 `diff`。
- **零成本起飞前检（`preflight`）与四态兼容矩阵**：把语法校验、单测、文档一致性检查与假模型冒烟收敛为一键免费前检，全绿后再触发付费模型调用；所有对外能力显式标死 `full | partial | deferred | not-goal` 消除范围模糊。
