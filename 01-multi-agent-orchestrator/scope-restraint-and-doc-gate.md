# 显式「暂不做与取回条件」克制账本 × 文档即代码契约门禁

> **核心产品与架构理念**：优秀的架构设计不仅取决于“决定做什么”，更取决于**清楚地记录“为什么现在坚决不做，以及在什么可证伪条件下才拿回来”**，并用自动化脚本把文档约束变成会报错的机械门禁。

---

## 一、显式「暂不做（Non-Goals）」与取回条件账本

在多 Agent 编排引擎 V2–V4 归零重构期间，所有被克制砍掉或暂缓的功能均不凭口头记忆丢弃，而是逐条登记在独立账本中（已满足条件落地后移入“已移出名单”）：

| 暂缓 / 删除项 | 真实代码现状 | 为什么现在坚决不做 | 可证伪的取回条件 |
| :--- | :--- | :--- | :--- |
| **1. 产出可见性双冗余开关**（`toUser` / `intoHistory`） | 源码 `src/` 零读取点，仅旧配置残留 | 释出物由 `release.from` 唯一指定，其余中间产出默认仅留执行轨迹；保留双开关徒增两套维护逻辑 | 真出现“某中间产物必须入历史”或“某产出需对界面隐藏”的具体用例，且取回首步必须真正接入源码读取 |
| **2. 12 个窄参数 Agent 专用配置工具** | 未建（改用通用编辑 + 静态校验器） | 12 个窄工具只为防填错参数，但徒增工具表上下文负担；2 个通用工具 + 1 个强校验器更省更稳 | 实测发现模型修改配置时反复改坏同一字段且静态校验器拦不住 |
| **3. 6 个未接线注意力阈值键**（`greenTokens` 等） | **已从活跃配置彻底删除**（此前 `src/` 零命中） | **留着不生效又看不出是假的，比没有更糟**；在界面展示位落地前拍脑袋定阈值毫无意义 | 界面注入提示位开工时再接回，并把门禁升级为“源码必须存在真实读取点” |
| **4. 存档目录 7 处细拆** | 压合为「配置 / 资产 / 存档」3 处 | 目录切太碎导致时间旅行回退与归档导出要跨 7 目录协调，极易留下半截态 | 单存档目录大到单次读取或导出出现可测性能瓶颈 |
| **5. 规划后五阶段远期排期** | 仅锁定前 3 阶段最小闭环 | 九段排期等于九张口头支票；核心链路（出正文 / 过审 / 记住）真机跑通前，远期排期全是纸面幻觉 | 前三段真机稳定运行后，按当时暴露的真实短板动态排期 |
| **6. 档案数组内单元素删除指令** | 支持整章 `null` 墓碑删除，数组仅并集追加 | 让模型可靠区分“本轮只提一条”与“删除旧别名”需引入显式删除语法，复杂度收益比暂不划算 | 真出现“旧别名/旧持有物被剧情明确作废且干扰后续推演”的高频痛点 |

> **账本闭环实证（已移出名单）**：原账本中两项曾暂缓的条目——「资产无损原样导出（导入再导出字节与 SHA-256 一致）」与「三段式向量化召回（精确命中 → 向量粗筛 → 精排）」——在真实需求触发后均已正式落地实现并从暂缓名单移出。

## 二、文档即代码契约门禁（`check-docs` 机械拦截规则）

文档腐化（与代码脱节、术语混用、含糊承诺）是 AI Coding 时代产生幻觉配置与需求误读的头号元凶。为此在引擎仓库内配套了零依赖自动化体检脚本（退出码 `0` 才放行），执行 **4 条机械硬检查**：

1. **核心文档与配置文件完整性**：强制检查 `README`、`REQUIREMENTS`、`TECH`、`glossary`、`failures`、`future`、`smoke` 与 `pipeline.json` / `worldbook.json` 全部存在、非空（`>= 200` 字节）且 JSON 可合法解析；
2. **杜绝“代码不读的假配置键”**：对 `config/pipeline.json` 的 `limits` 块仅校验**源码中存在真实读取点的键**（如 `historyFloors`、`maxSections`），果断剥离未接线的假开关，防止“改了配置毫无反应”的调试黑洞；
3. **机械封杀模糊词与未来时态**：全量扫描 7 份核心 Markdown 文档，命中 **`将会`、`计划中`、`原则上`、`尽量`、`待定论`、`以后再`、`未来会`** 任一词直接报行号红灯失败——逼迫所有规格写清“现在是什么”或正式移入《暂不做账本》；
4. **单一权威术语表强制一致**：除术语表自身豁免外，机械拦截 **`节点` / `环节`（统一叫「步骤」）、`审稿`（统一叫「审」）、`实体`（统一叫「档案」）** 等混用词，确保人与 AI 在全仓共用同一套精确概念映射。
