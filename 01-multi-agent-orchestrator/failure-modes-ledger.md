# 失败模式 → 机械硬约束账本（Failure Modes → Mechanical Constraints）

> **核心工程原则**：每一个已知的线上或压测故障，都必须配一条可机械拦截的硬约束。**不靠“模型或人小心一点”，靠会主动报错并拒绝执行的确定性机制。**  
> 本账本脱敏整理自多 Agent 编排引擎从 V1（`867` 条绿测却潜藏 7 处真机假接线）归零重构至 V2–V4（`306/306` 单测 <1 秒全绿 + 文档/配置契约门禁零告警）的全周期踩坑记录。

执行位置分级：
- **配置校验**：启动或保存草稿时静态拦截，不合法直接拒绝生效；
- **引擎**：运行期代码抛错、截断、拒写或原子回退；
- **界面**：可视化高亮标红、禁灰或展示让位/诊断明细；
- **工具 / 交付流程**：Agent 工具调用期直接拒执并回显具体原因，或由自动化门禁拦截提交。

## 1. 管线与执行

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 步骤重名 | 两个同名步骤，下游取产出时分不清来源 | 启动/保存时静态校验，重名直接拒绝 | 配置校验 |
| `see` 引用不存在的产出 | 某步莫名少了一块上下文仍继续运行 | 静态拓扑校验所有引用，精准报出失效字段 | 配置校验 |
| 多产出未切全 | 声明三份只切出一份，后续步骤拿到空值 | 多产出缺任一份即报错，绝不拿全文兜底 | 引擎 |
| 让模型手工维护闭合标签 | 开了标签忘关或重复开闭，整轮白烧 Token | 单产出由引擎预填开标签并自动补闭；多产出宽容截取记诊断 | 引擎 |
| 产出比声明多 | 额外内容悄悄丢失且用户无感知 | 切出产出集合与声明不符即显式告警/报错 | 引擎 |
| 改配置后行为未变 | 以为改了参数，实际仍在跑旧缓存 | 配置绑定指纹，界面实时展示当前生效版本 | 引擎 + 界面 |

## 2. 上下文可见性隔离

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 下游越权读到不该看的内容 | NPC 提前知晓尚未发生的剧情或他方秘密 | 默认全部关闭；仅白名单 `see` 显式声明才可见 | 引擎 |
| 内部草稿/思考混入用户正文 | 正文冒出“场景：”“节拍：”等编排内部产物 | 进历史与向用户释出分离为独立开关，默认全关 | 引擎 |
| 上轮内部思考回灌污染下轮 | 本轮模型照抄上轮内部思考格式 | 产出显式标记 `@prev` 才跨轮传递，否则仅限本轮 | 引擎 |

## 3. 独立审校与打回闭环

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 先向用户展示再送审 | 用户已看到劣质内容才触发审校 | 审校严格置于释出之前；未过审不落会话历史 | 引擎 |
| 判决只给结论不给理由 | 只说“不通过”，上游重写不知改哪 | 判决格式必须含原因字段，缺失即判配置不合法 | 配置校验 |
| 打回导致整条链路重跑 | 改写手却把导演前置步骤重跑一遍 | 精准退回产出目标步骤，下游尚未启动零浪费 | 引擎 |
| 判官死循环打回 | 卡死耗尽 Token 既不出正文也不报错 | `retries` 必填且来自配置，触达上限即熔断停机 | 配置校验 + 引擎 |
| 判官理由段触发子串误判 | 理由写“虽然前半句通过，但整体不通过”被误判通过 | `readVerdict` 仅扫前 5 个非空行且**先判否定再判肯定** | 引擎 |
| 审校漏放劣质稿 | 过审正文仍存在隐蔽瑕疵 | 完整判决与打回链路写入执行轨迹，用户可事后复核 | 界面 |

## 4. 状态变量与数值结算

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 引擎硬编码业务变量名 | 换题材/换资产卡立刻崩溃或静默失效 | 变量 Schema 全量由外部资产声明，引擎代码零具体变量名 | 引擎 |
| 数值晚于正文更新一屏 | 正文已扣资源，状态栏仍显示旧满值 | 状态结算在释出前同步完成，与正文同刻展示 | 引擎 |
| 越界数值写入存档 | 声望/好感溢出上限变成 150 | 按 Schema `min`/`max` 确定性夹取，界面显式标注 | 引擎 |
| 未声明幻觉键混入状态 | 资产未定义的字段被模型凭空造出 | 未在 Schema 声明的键一律丢弃 | 引擎 |
| 结算 JSON 解析失败卡死主流程 | 结算异常导致已生成的优质正文丢失 | 解析失败时正文照常释出，状态栏标记“本轮作废” | 引擎 |
| 模型漏写字段或用空串抹旧值 | 整张状态表被重置或历史值被 `""` 覆写 | 强制增量更新 + 递归空串剪枝（保留历史值） | 引擎 |

## 5. 长期档案与人机共治（HITL）

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 模型擅自修改长期设定 | AI 在后台静默篡改核心设定且无法追溯 | `applyProposal` 物理不暴露为模型工具；仅人带原话确认可写盘 | 引擎 + 工具 |
| 提案审批期间状态已漂移 | 几轮前生成的修改提案覆写最新剧情状态 | 落盘前逐条 CAS 重验旧值，任一条失配整份拒写 | 引擎 |
| 同一实体分裂多个档案 | 同一 NPC 被建出多份冲突档案 | 实体主名与别名全局唯一，写入前强制查重 | 引擎 |
| 短名模糊替换误伤同名实体 | 改“角色甲”时误替换“角色甲乙” | 修改与删除一律要求完整原文精确匹配，失配即报错 | 引擎 + 工具 |
| 同级分类语义包含爆炸 | AI 不断新建“人物/核心人物”导致目录腐化 | 新增分类检测同级互包含直接拦截 | 引擎 |
| 记录缺少来源楼层 | 时间旅行回退后档案残留未来记忆 | 所有档案记录与章节强制绑定来源楼层，缺即拒写 | 引擎 |

## 6. 回退、存储与存档完整性

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 只截断消息不截断状态 | 回退对话后数值与档案仍停在未来楼层 | 7 类存储统一注册 `STORES` 接口，按楼层联动截断 | 引擎 |
| 回退中途进程崩溃留下半截态 | 部分存储已删、部分未删致存档损坏 | 回退前先写 `回退中.json` WAL 标记，`meta.floor` 最后写，重启幂等恢复 | 引擎 |
| 误点回退无法反悔 | 长程存档历史楼层永久丢失 | 被截断数据移入回收站配 `清单.json`，支持一键 `undoRollback` | 引擎 + 界面 |
| 导出归档包损坏或漏配置 | 日后复现时发现配置漂移或包无法打开 | 归档包强制附带配置快照，导出后自动回读校验 | 引擎 |

## 7. 知识库 / 世界书检索

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 同书条目重名 | 工具修改无法确定目标条目 | 同书内重名直接拒绝写入 | 工具 |

| 调整 UI 文件夹改变触发逻辑 | 仅做目录整理导致线上行为变化 | 文件夹仅作展示不参与任何判定，测试强制断言 | 引擎 |

## 8. 工程卫生与 AI Coding 防腐（源自 V1 复盘）

| 失败模式 | 故障表象 | 机械硬约束 | 执行位置 |
| :--- | :--- | :--- | :--- |
| 单测全绿但真机功能未接线 | V1 出现 867 条绿测却潜藏 7 处假接线 | 确立证据金字塔（亲眼看 > 真机跑 > 接口通 > 单测过） | 交付流程 |
| 存在“代码不读的假配置键” | 改配置毫无效果误导调试 | `check-docs.mjs` 静态断言每个配置键在源码均有真实读取点 | 自动化门禁 |
| 单文件失控膨胀 | V1 单文件达 5,500+ 行，改一处牵动全局 | 设立 5 条体量停止信号（改 3 轮 / 跨 >5 文件等立刻停手拆解） | 协作规范 |
| 文档充斥模糊词与术语漂移 | “原则上/尽量/节点与步骤混用”致 AI 误读 | 文档门禁机械拦截模糊词与非标准术语，改字段同批改文档 | 自动化门禁 |
