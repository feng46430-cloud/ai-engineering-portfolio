# 多 Agent 提示词分层与防污染模式（Engineering Patterns）

---

## 模式一：多 Agent 提示词与知识库「三问归属法」

在多 Agent 流水线中，最常见的烂架构是“把所有要求往每个 Agent 的 Prompt 里各贴一遍”，结果 Token 爆炸且上下游互相打架。我们在重构多 Agent 提示词时建立了唯一归属判定法——**任何一条新需求入库前必须连续过三问**：

1. **这一步看得见吗？（Visibility Check）**  
   每个步骤的提示词**只能约束其 `see` 白名单内可见的数据**；看不见的字段写进提示词纯属噪声污染。
2. **这一步有权决定吗？（Authority Boundary）**  
   严格隔离职责边界：规划 Agent 只定路径与目标、状态 Agent 只定实体状态变化、生成 Agent 只负责最终表达、审校 Agent 只出判决与返工理由——严禁越权把下游权力塞进上游。
3. **这是「判据」还是「素材」？（Rule vs. Knowledge Decoupling）**  
   - **判据**（行动准则、输出底线、审校标准）→ 进对应 Agent 的提示词；
   - **素材**（静态设定、领域词表、历史档案、数值分档）→ 进结构化知识库 / RAG 按需检索。

## 模式二：防元叙述污染的「双标记提取 + 启发式回退」解析契约

- **真实线上故障**：在自动摘要/提炼类 Agent 中，真实模型偶发会把“用户要求压缩摘要、写 3–6 句……”等指令元叙述直接吐在正文前，若直接落盘会永久污染后续上下文。
- **工程解法**：
  1. **主路径（显式边界契约）**：由引擎 `contract.mjs` 自动注入首尾显式定界符（如 `【输出开始】…【输出结束】`），解析器优先提取定界符区间；
  2. **宽容降级（应对漏闭标签）**：当模型遗漏闭合标签时，只要开标签存在则截取至文末并写入 `removed / diagnostics` 告警，不无谓触发整轮失败重试；
  3. **回退过滤（应对完全无标记）**：当定界符缺失时，回退至元信息段落过滤器并配套**双路径单元测试**覆盖，确保两条路径均零脏数据落盘。

## 模式三：多 Agent 调用压缩与安全熔断（12 次 → 4~5 次）

在另一套本地多角色编排工作台（`preset-cot-workbench`）的实测迭代中，最初拆得过细导致单轮需要 12 次工具调用，延迟高且极易撞爆宿主 5 次递归工具上限：
- **合并低耦合阶段**：将筹备类 3 个独立调用合并为 1 次结构化 Schema 调用，将后场 3 位审校顾问合并为 1 次「圆桌一票否决严审」调用，单轮总调用量从 **12 次压缩至 4~5 次**；
- **解除 JSON 工具笼**：最终生成阶段恢复主模型纯文本流式输出，大幅改善首字延迟（TTFT）与表达自然度；
- **渐进式工具披露 + 递归熔断阀**：按阶段动态暴露工具（Stage 2 工具仅在 Stage 1 完成后解锁），并设置整轮规划退回次数安全阀（`= 1`），杜绝死循环与吞输出故障。

## 模式四：隔音室盲投 → 亮牌多轮辩论 → 实证仲裁（Multi-Agent Debate 防从众偏置）

在 13,128 行多 Agent 编排工作台（`preset-cot-workbench`）中，针对传统多 Agent 串行讨论极易产生**“首发言锚定 / 集体从众（Groupthink）”**的问题，落地了三阶段独立研讨架构：
1. **第 1 轮（隔音室全并发盲投）**：多位不同职责/视角的专家 Agent 在互不可见的隔离上下文中并发独立产出初判，彻底消除首位发言锚定偏置；
2. **第 2..N 轮（真多轮亮牌互怼）**：每位 Agent 读取其他成员原话，同时**延续自身上一轮私有记忆**展开针对性反驳与补充；
3. **终轮（主席拍板 + 可选外部检索查证）**：仲裁 Agent 汇总分歧、按需触发本地 SearXNG/Wikipedia 实证核查并定稿 Final Plan，最终主生成模型只需跑 1 趟专心输出。

## 模式五：超长程多轮交互防崩与「短输入 / 空转节拍」治理

在实测跑通 **678 轮（50 MB）** 与 **400 轮（18.7 MB）** 超长程状态驱动多轮交互中，沉淀出两套直接面向 AI 陪伴 / AI 原生游戏核心痛点的工程方法：
- **规则体系工业化重构与冲突审计**：针对复杂多世界书/状态规则先做只读冲突审查（曾单次拦出互斥触发时间、3 时点争抢结算竞态、用不存在的 Schema 字段防重结算等 **10 项系统硬冲突**），再按四段标准骨架（`【核心】/【规则】/【判据】/【反例≤1】`）执行「一条一判据 + 彻底中性化 + 条目独立自洽适配按需 RAG」重构（12 条规则从 `11,864` 字压减 **≥35%** 至 `≤7,600` 字）；
- **专治「短输入空转」与「上下文误触」**：定义短输入场景的跃进五项必须与禁止收尾清单（杜绝逼用户做选择、无意义复盘/汇报收尾）；配套**全局上下文 X 光（U 型注意力热力分区）**、**`<尖括号>` 结构化标签扫描护目镜（防状态标签误触 RAG 关键词）** 与 **无损聊天分层瘦身引擎**（零修改底层存档）。

## 模式六：三层 Prefix Cache 防击穿保护与快慢模型尾块拆流

在长程多轮与多步工具调用编排中，任何前缀漂移都会让整段上万 Token 的供应商 KV Cache 失效重算，同时破坏推理模型的思考签名：

1. **静态前缀与动态状态物理分层**：卡片世界书将静态世界观、总则与生态阶梯锚定在 `before_char` 稳定前缀区；每轮高频变动的状态变量更新规则与动态裁定结果压在 `after_char` 末尾紧贴生成游标。
2. **编排引擎级缓存锚定（源码铁律）**：
   - 将 Preset Front 固化写入会话轨迹，避免手动/定时/原生压缩（compaction）回放时从首 Token 偏移击穿缓存；
   - 多步工具调用循环中，将 Back 阶段锚死在「本轮用户输入之后、首条回复之前」绝不后移，同时保住 **推理链校验签名（Thinking Signature）** 与后续每步的 **Provider Prefix Cache**；
   - 状态快照序列化强制保持 JSON/YAML 键序稳定，防止键序抖动打碎缓存命中。
3. **快慢模型拆流（尾块外包专员）**：主模型专心流式输出高质量正文（解除 JSON 工具笼），流式结束后由廉价快模型约 2 秒同步补齐摘要、弹幕、考据与结构化状态尾块，兼顾文风、首字延迟与成本。
